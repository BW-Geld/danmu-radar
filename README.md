# 弹幕雷达 · 斗鱼弹幕统计工具

本地运行的斗鱼直播间弹幕采集与统计软件。零第三方依赖（只需要 Node.js），数据全部存在自己电脑上。

- 采集的是**公开弹幕**，不登录、不碰账号、不发弹幕
- 不用任何 API key / Cookie / 第三方服务
- 一个进程 + 一个 SQLite 文件，关掉就是关掉

---

## 快速开始

### 便携版（什么都不用装）

1. 解压 `弹幕雷达-便携版.zip` 到任意目录（比如 `D:\弹幕雷达`）
2. 双击 **`弹幕雷达启动程序.vbs`** —— 没有黑色命令行窗口，程序在后台跑；`弹幕雷达-调试启动.bat` 是带窗口的调试版，只在启动不起来时用
3. 想要桌面图标：双击 **`在桌面创建快捷方式.vbs`** 一次，桌面就多一个带图标的「弹幕雷达」，以后点那个就行（`.vbs` 这类脚本文件的图标是 Windows 按扩展名定的，改不了，只能靠快捷方式）
3. 会弹出一个独立窗口（没有地址栏和标签页），地址是 `http://127.0.0.1:7788`
4. 在「实时弹幕」页输入房间号（`6657` 也行，`https://www.douyu.com/6979222` 也行），点「添加」

> 退出：关掉独立窗口（默认缩到托盘继续采集），或托盘右键「停止采集并退出」，或设置页「停止采集并退出」。
> 用 `弹幕雷达启动程序.vbs` 启动时，程序输出写在 `data\server.log`（超过 5MB 自动轮转成 `server.log.1`）。

### 从源码跑

需要 Node.js 22+（在 v24 上开发验证）。

```bash
node --disable-warning=ExperimentalWarning server/index.js
```

然后浏览器打开 `http://127.0.0.1:7788`。

> 不需要 `npm install`：没有依赖、没有构建步骤、没有前端框架。

### 打包便携版

```bash
node tools/build-dist.js         # 生成 dist/弹幕雷达-便携版/
node tools/build-dist.js --zip   # 再压成 zip（约 33 MB）
```

打包做的就是把当前 `node.exe`、`server/`、`web/`、`shared/`、`tools/tray.ps1`、`弹幕雷达启动程序.vbs`、`弹幕雷达-调试启动.bat`、`在桌面创建快捷方式.vbs`、`assets/danmu-radar.ico`、`使用说明.txt` 复制到一起。`node.exe` 用的是本机装的那个（约 87 MB 未压缩），放在 `runtime/` 子目录里——根目录只留用户会去点的那几个文件，免得有人直接双击引擎。

## 一、实时弹幕

- 添加房间后**自动开始采集**，断线自动重连（指数退避），主播下播会显示「已离线」，开播自动恢复。
- **弹幕潮**：10 秒内同一句话被 ≥3 个不同用户刷出来，算一次潮。左下角列出最近的潮（按 10 秒桶统计、相邻桶合并），点一条直接去检索。潮期间的弹幕**不会被当成重复丢掉**。
- **跟读**：贴底时自动跟新；往上翻不会被新弹幕拽走；翻回底部自动恢复；右上角有「↓ 回到最新」。

## 二、关键词检索

三个召回途径，每条结果都写明**为什么被命中**：

| 途径 | 说明 |
| --- | --- |
| 精确命中 | 归一化后（去标点、转小写）做子串匹配 |
| 同义 / 梗词扩展 | 12 组斗鱼常用词（开团/冲/上啊、抽奖/白嫖/欧皇…），可在「设置 → 自定义词表」里加 |
| 强相关 | 对命中的每条弹幕取前后 ±90 秒上下文，统计「一起出现」显著高于背景的词（lift） |

**结果按句子聚合，不按条铺开**：一场直播里同一句话被几百人刷，逐条列出来没法看。所以一行 = 一种说法，前面标着 `×N 条 · M 人`，点「展开」能看到：

- 本库最早是谁、什么时候发的
- 共 N 条 / M 人、被 +1 多少次、弹幕潮几次
- 谁在发（12 个昵称，点一下跳到用户页）

**高频词推荐**：搜索框下面那排词是当前房间最近 2 小时的高频词，点一下直接搜。它做了三件事：不做 n-gram 拼接（避免「是明」「会胖」这种跨词碎片）、剔除弹幕潮本身的说法、合并近似变体（`胖哥两烧烤` / `胖哥俩烧烤` 算一条）。

**筛选与导出**：可以按房间、按时间（今天/7 天/30 天/全部）过滤；「导出 CSV」取的是**全部命中**，不是当前这一页（页面上最多显示 300 条，会提示「列表只显示最近 300 条」）。

## 三、用户

左边是关注列表，右边查人。

**关注**：打开任意用户后点右上角「关注」，TA 就进左边的列表；点名字直接看 TA 的页面，点 × 取关。关注只是本地 SQLite 里的一张表（`follows`），不上传任何地方。

**页面分区**（从上到下）：行为特征（六维 + 标签 + 明细）→ 房间分布 → 活跃时段（按小时，柱顶有数字，点柱子跳到那一小时）→ 发得最多的一类 → 高频发言 → 活跃分布（按天）→ 历史弹幕 → 判定依据。

- **六维**：活跃度、房间黏性、话题多样性、对立倾向、程序化倾向、消费行为。
- **对立倾向**分三层：骂人满权重（19 个脏词）、拱火半权重（21 个节奏词 + 「你急/就急/急啥…」+ ≤8 字的裸「急」）、阵营词必须同句带挑事语气才算（只说「我是龙美」不算）。点「直接 X 条 · 拱火 Y 条」能看每一条原话。
- **历史弹幕**：这个用户的**全部**弹幕，按时间倒序，**不聚合、不查重**——同一句话刷三遍就是三条。列表固定高度、在框里滚动，滚到底自动续下一页（每次 200 条）。
- **在历史弹幕里搜**：卡片右上角有个搜索框，只在这个用户的发言里找（子串匹配，跟检索页一致）。输入停 300 ms 才查；标题变成「匹配「x」N 条」，命中的词高亮；清空（或按 `Esc`）恢复全量。搜索走服务端，所以**没加载出来的历史也能搜到**，不是只筛眼前这 200 条。
- **活跃分布（按天）**：只有一天有发言时直接给一行可点日期，多天时画柱状图，点柱子跳到那天的时间线。
- 样本太少时标签只有「样本偏少」，不会硬猜。

## 四、排行榜

两张榜，**可以选日期**：今天 / 选日期 / 全部。另有房间过滤和前 20 / 前 50 / 前 100。

- **发言榜**：按 uid 聚合的条数排名，点昵称跳用户页。
- **被 +1 最多的弹幕**：按「说法」聚合。**+1 次数 = 该说法总条数 − 1**（第一条是首发，之后每跟一条算一次），同时给出总条数、参与人数。

口径说明：这张榜统计的是「说法」不是「单条弹幕」（`哈哈哈` 和 `哈哈哈哈哈` 算同一种）；`+1` 也不等于抄袭，跟风、玩梗、复读都算在内。

## 五、时间线

选一天 → 24 小时时间线（每根柱子 = 1 分钟的弹幕条数）→ 在图上拖出一段：

- 选好后**固定住**，拖两端可以微调；点「清除选区」或按 `Esc` 取消
- 起止时间显示在时间线**外面**，图上两端各有一个时间牌
- 结果按重复次数降序：`×N 条`、首次出现时间、被 +1 次数、点「在检索里看」直接去搜
- 选区会记住（按日期+房间存本地），刷新还在
- 从检索结果的「本库最早」时间、或用户页的小时柱，都能**直接跳进来**（分别落 5 分钟 / 1 小时）

## 六、收藏夹

收藏的是「说法」不是某一条弹幕。点一下星标就收藏，再点取消。列表里显示当前条数、人数和收藏时间，点一条直接去检索。

## 采集原理

1. 用房间号（或短号/别名）请求 `https://www.douyu.com/betard/{key}` 拿 `room_id`；短号查不到时退回解析房间页里的 `"room_id"`
2. 用 TLS 手写 WebSocket 升级，连 `danmuproxy.douyu.com:8501-8506`
3. `loginreq` → 收到 `loginres` → `joingroup gid=-9999`（游客分组），45 秒一次 `keeplive` 心跳
4. 帧格式是 `[4 字节长度][4 字节长度][4 字节 689][正文+\0]`，一条 WebSocket 帧里可能拼了多条消息，必须按长度前缀循环切分

弹幕字段：`uid / nn（昵称）/ txt（正文）/ cst（时间戳）/ level / bnn（粉丝牌）/ bl（粉丝牌等级）/ brid`。

**断线会丢数据**：实测断网 118 秒，重连后 `dropped=0`、`replayDropped=0`、没有旧时间戳批量涌入——斗鱼**不补发**错过的弹幕，那 118 秒的消息永久丢失。所以有了「采集缺口」台账。

## 数据口径与已知限制

**去重分两层**，因为斗鱼补发有两种可能：

1. **指纹层**：`chatmsg` 没有弹幕唯一 ID，用 `sha1(房间|毫秒时间|正文|类型)` 建唯一索引（**不含 uid**，否则匿名库包和实名库包对不上）。挡住「原样重发」。
2. **重连窗口层**：如果服务端补发时重打了时间戳，指纹就变了。所以重连成功后开 90 秒窗口，窗口内同一用户发同样的话按补发丢弃。

计数器都在 `/api/stats.runtime`：`dropped`（指纹层拦下）、`replayDropped`（窗口层拦下）、`lateFrames`（收到的帧比水位更早的次数）。

**连发 / 弹幕潮**：去重层拦下的不是垃圾，每条都写进 `dupes` 表留档。10 秒内同一句话被 ≥3 个不同用户刷出来时判定为潮，此时**不做**补发去重（否则会把全房复读当成重连补发删掉）。

**采集缺口（gaps）**：断网、程序关闭都会记一条缺口（`reason` 区分 `reconnect` / `downtime`），短于 10 秒的丢弃、相邻的合并。画像里的「发言时间跨度」会把它标出来——**偏差只会少算，不会多算**。

**检索是子串扫描**：`ntxt LIKE '%词%'` 用不上索引，耗时随行数线性增长。实测 1.2 万行约 5 ms（单查询），30 万行约 0.1–0.2 s。

**检索会慢在「按说法分组」上，不是 LIKE**：一次检索要跑三次 `COUNT`（精确 / 同义 / 强相关）再加一次分组。9 万行、`哈哈`（1494 条命中）实测：`searchMessages` 9 ms、`countByTerms` 16 ms、分组 322 ms，总计 2.5 s。分组之所以慢，是它对**每一组**各跑一次 `WHERE COALESCE(NULLIF(stem,''),txt) = ?`——表达式用不上索引，等于每组一次全表扫（40 组 = 40 次扫）。改成「一次 `IN (...)` 把前 N 组的最新行取回来，在内存里挑最长的一版当样本」后，同样查询 **2.5 s → 253 ms**（开强相关 550 ms）。`tools/probes/probe-search-cost.js` 把这两条做成预算断言（1800 / 2400 ms），超了就报红。

**弹幕有三种来源**：`live`（本机采集）、`vod`（录播导入）、`import`（别人的库包）。检索结果里分别标「录播」「导入」，画像页头部写「其中直播采集 X 条 · 录播 Y 条 · 导入 Z 条」。`import` 的弹幕 uid/昵称是导出方抹过的（匿名包）或原样带来的（实名包），看画像时要记得这点。

**FTS5 测过但没采用**：本机 SQLite 支持 FTS5 与 `trigram`，1.2 万行建索引 41 ms、三字以上查询从 5 ms 降到 0.1 ms、结果一致。但 **trigram 要求查询 ≥3 个字符**，而中文关键词大多是 2 个字（抽奖、开团、哈哈），这些仍得全表扫描——收益只覆盖一半场景，却要承担索引与主表不同步的漏召回风险。等语料接近 30 万行再评估。

**文案检查**：所有面向用户的措辞集中在 `shared/copy.js`，由 `node tools/copy-lint.js` 检查——禁用「喜欢 / 偏好 / 感兴趣 / 最爱 / 热衷」，`web/` 源码里也不许出现。这是窄规则，另外的约定是：新增文案一律先进 COPY，不在 `analysis.js` 里拼字符串。

**观测点**：`/api/stats.runtime` 给出 SSE 连接数、待落库缓冲、丢弃数、WAL 大小、进程内存、运行时长、上次自动清理时间。挂机时看这里比盯控制台可靠。

### 停止 vs 删除

| 操作 | 采集 | 重启后 | 历史弹幕 |
| --- | --- | --- | --- |
| 停止 | 立即断开 | 不会自动重连（`auto_start=0`） | 全部保留 |
| 删除（不勾选数据） | 断开、从列表移除 | 列表里没有它 | 保留（以「仅历史」身份出现） |
| 删除数据 | 断开、从列表移除 | 列表里没有它 | **一并删除**（`messages`/`dupes`/`gaps`/`flood_events`） |

### 关窗口：缩到系统托盘，或者停止采集

设置里「关窗口时」有两个单选，它决定点 × 之后怎么办；**右上角那个小药丸**显示的就是当前这个选择（「关窗口后缩到系统托盘继续采集」/「关窗口 30 秒后停止采集」），点一下直接跳到这张设置卡。关窗口按钮（×）属于浏览器，我们拦不到，只会按这里的设置执行。

选「缩小到系统托盘」后：独立窗口会被服务端直接关掉；如果你是在**浏览器标签**里点的，标签页得你自己关（脚本关不掉不是自己打开的标签），界面会提示这一点。

| 选择 | 关掉界面之后 | 怎么回来 |
| --- | --- | --- |
| 缩小到系统托盘（默认） | 采集继续；界面全断开后托盘图标会自动出现 | 双击图标回到界面，右键「停止采集并退出」 |
| 停止采集 | 先等宽限期（默认 30 秒，期间重开页面就继续），超时后停止并退出 | 重新启动程序 |

为什么不弹系统确认框：Chrome/Edge 119 起忽略页面自定义的 `beforeunload` 文案，只会显示自带的「你所做的更改可能未保存」，既改不了也说不清。所以关窗口直接放行，由右上角那个药丸常驻说明当前会怎样。

「界面全断开」是怎么判断的：SSE 连接数归零（`/api/stream` 的客户端集合）。所以关掉最后一个界面（标签页或独立窗口）之后，服务端会在 2 秒内接手——托盘模式下把图标拉起来，停止模式下开始宽限倒计时。

托盘实现是 `tools/tray.ps1`（Windows 自带 WinForms，不起额外进程树，服务退出时它自己消失）。两个坑：脚本必须存成 **UTF-8 带 BOM**，否则 PowerShell 5.1 按 ANSI 读会解析失败；从 Node 拉起时**不能用 `detached`**，`DETACHED_PROCESS` 下 PowerShell 会立刻退出（实测 exit 0、脚本一行没跑）。

## 录播弹幕导入（冷启动用）

斗鱼没有历史弹幕接口，但视频站的回放有完整弹幕。粘一个 `https://v.douyu.com/show/xxxx` 或 12 位以上的 showId，先「预览」看条数和时长，再「导入」。

实测同一接口的三个样本：

| showId | 时长 | 弹幕数 | 独立用户 | 人均条数 | 密度 |
| --- | --- | --- | --- | --- | --- |
| `6Aw87Ogqmxj7YGkg` | 52 分钟 | 10408 | 3365 | 3.09 | 200 条/分 |
| `yVY8WwG3j9PWLOz9` | 30 分钟 | 3165 | 1016 | 3.12 | 106 条/分 |
| `2V0JMV10OYD7RY5k` | 4.5 分钟 | 626 | 394 | 1.59 | 138 条/分 |

- 导入的弹幕带 `source = vod` 标记，检索结果里显示「录播」标签；从别人的库包导入的是 `source = import`，显示「导入」标签。画像页头部会写「其中直播采集 X 条 · 录播 Y 条 · 导入 Z 条」。
- 时间戳：完整回放的每条弹幕都有自己的发送时间；少数剪辑片段所有弹幕共用同一个 `sts`，这时用 `sts + tl`（视频内偏移）推算。
- **定位**：录播适合补**检索语料**，对**画像**帮助有限——人均 3 条撑不起可信标签。画像仍要靠长时间实时采集。
- 批量发现「某主播最近 N 场回放」的接口尚未接入（`getAuthorVideosByNew` 已可用，但拿不到「完整回放」的列表，视频站以剪辑为主）。

## 弹幕库分发（导出 / 导入）

导出的是一个独立的 `.db` 文件（SQLite），用任何数据库工具都能打开检查；别人在「导入」里选中它，语料就并进自己的库。同一条弹幕按内容指纹去重，重复导入不会翻倍。

- **匿名库包（默认）**：没有 UID 也没有昵称——每条弹幕的 uid 写成 0、昵称写成「匿名」，只保留正文、时间、房间和计数。可以公开分给别人。
- **实名库包**：带每条的 UID 和昵称，只建议在自己设备之间同步。
- 粒度：整库 / 按房间 / 按时间段。
- 导入后自动重算词条分类与弹幕潮事件。

## 常见问题

**能不能采集别人的历史弹幕？** 直播只能边看边存。录播可以——在「设置」里贴 `v.douyu.com/show/...` 导入。

**为什么我导入的录播只有几百条？** 那是剪辑片段，不是完整回放。预览时会显示时长，几分钟的就是剪辑。

**双击「弹幕雷达启动程序」没反应 / 没打开窗口？** 看 `data\server.log`（那里有启动日志）。常见三种：① 端口 7788 已被占用（程序已经在跑）；② 杀毒软件拦了 `node.exe`；③ 手动访问 `http://127.0.0.1:7788` 看是否已经在跑。实在看不懂就双击 `弹幕雷达-调试启动.bat`，它会带窗口跑一遍并显示报错。

**数据在哪？换电脑怎么办？** 全在 `data\danmaku.db`。整个 `data` 文件夹拷走就是全部数据；也可以用「弹幕库分发」导出一个包带走。

**大房间会不会把磁盘写满？** 会。大房间约 30 条/秒、90 天约数 GB。默认按 90 天自动清理；勾「永久保留」就完全不删，注意磁盘。

**短号房间**：`6657` 这种短号查不到 `betard` 接口（返回房间页 HTML），程序会退回解析房间页里的 `"room_id":6979222` 再查一次。短号、别名都能直接填。

**弹幕会去重吗？** 会，但只挡「同一个人、同一毫秒、同一句话」——现实中断线重连的重复推送会这样。真刷两次（时间不同）仍算两条，这是统计活跃度的基础。

## 打包：为什么发便携包，而不是单文件 exe

单文件 exe 是可行的，实测过（Node 24 的 SEA）：

| 验证项 | 结果 |
| --- | --- |
| `node:sqlite` 能不能带 | 能，不需要额外 `--experimental-sqlite` |
| 数据路径落在哪 | `process.execPath` = exe 自身，**不抽取到临时目录**，`data/` 就在 exe 旁边 |
| WAL 能不能用 | 能，运行时 `-wal`/`-shm` 都在，关闭后只剩 `.db`，二次运行可读 |
| 体积 / 启动 | 87.3 MB；冷启动 110–123 ms（对照 `node -e 1` 86–98 ms） |

没走这条路的原因是：`postject` 改过字节的 exe 会丢数字签名，是杀软误报高发对象；而且用户想改一行配置都得重新打包。便携包看得见摸得着，出问题能直接看文件。
